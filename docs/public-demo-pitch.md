# Agentic Payments Lab — Public Demo Pitch

A grounded write-up of what the project is, what the local demo proves, and
where it is intentionally not yet. Target reader: AI engineers, Web3
engineers, technical founders, and product or investor people interested in
agentic commerce.

## Problem

AI agents are starting to call APIs on behalf of users — for data, tooling,
research, market intelligence, and risk analysis. Most of those APIs still
assume a human-managed billing relationship: an account, a credit card, a
subscription. That model does not compose well with agents that need
short-lived, pay-per-call access, often across services they discover at
runtime.

There is no widespread, agent-native answer to a simple question: how does
an autonomous client pay a service it just discovered, for exactly the call
it is about to make, with auditable evidence on both sides?

## Insight

The web already has an HTTP status code reserved for this exact case:
`402 Payment Required`. The [x402](https://x402.org/) specification turns
that into a concrete protocol: the server replies with structured payment
requirements (network, asset, amount, receiver, expiry), and the client
either pays in a follow-up request or declines.

That gives us a clean separation:

- the **service** declares its price and accepted rails;
- the **agent** decides whether to pay, using its own policy;
- the **rails** are stablecoins on programmable chains, not subscriptions.

Agentic Payments Lab is a local proof of concept of that pattern, applied
to a service an agent would actually want: a structured DeFi position risk
report.

## Demo

One command from the repository root:

```
npm.cmd run demo:local
```

The demo:

1. Starts a local seller (`seller-api`) pinned to Base Sepolia (testnet) and
   a tiny price ceiling.
2. Calls a public mock endpoint, returning a structured DeFi risk report
   from a DeFi Guardian mock adapter.
3. Runs the buyer (`buyer-client`) in dry-run against the paid endpoint.
   The buyer parses the `HTTP 402 Payment Required` response, decodes the
   x402 requirements, and exits without signing.
4. Updates JSONL audit logs on both sides.
5. Renders and exports a self-contained dashboard
   (`dashboard/index.html`) summarizing seller events, buyer events,
   offers, dry-runs, reports, and correlated request IDs.
6. Stops the seller and prints `RESULT: LOCAL_DEMO_SUCCEEDED`.

There is no key, no faucet, no funding, and no mainnet traffic required to
run the default demo. There is also a previously validated controlled
payment path (Base Sepolia USDC, micro amount) that is deliberately kept
out of the default flow.

## What It Proves

- An agent client can discover a paid API at runtime via x402, parse its
  terms, and decide whether to pay.
- A service can charge per-call for a structured, agent-consumable output
  (here: a DeFi position risk report) instead of a subscription.
- The full flow leaves an auditable trail on both sides — request IDs,
  offers, dry-run decisions, generated reports — and that trail can be
  aggregated into a local KPI dashboard from sanitized logs only.
- The same plumbing has been driven through a real testnet payment, so
  the path from dry-run to actual stablecoin settlement is not theoretical.

## Why x402

- It reuses HTTP semantics; any existing HTTP client can be taught it.
- The server declares its price; the client decides whether to pay. No
  shared account or subscription state is required.
- It is rail-agnostic in spirit: the same shape works for different
  stablecoins and networks. Here, the demo uses USDC on Base Sepolia.
- It maps naturally to agent decision loops: "I need this data, the price
  is X, my policy allows up to Y, proceed or skip."

## Why DeFi Reports

A DeFi position risk report is a useful concrete example because:

- It is high signal (range status, risk level, recommendation) and
  structured enough for an agent to act on.
- It is a service many users would conceivably pay an agent to fetch
  before rebalancing, exiting, or sizing a position.
- It demonstrates a class of agent-consumable services that benefit from
  pay-per-call rather than subscription.

In this lab the report is generated by a mock adapter that imitates the
contract of a real DeFi Guardian engine. The seller exposes the same
shape on `/paid/defi-risk-report` (gated by x402) and a public
`/mock/defi-risk-report` (no payment) so the demo can show the contract
without exercising payment.

## Current State

Implemented:

- x402 buyer/seller scaffold (Express + TypeScript, Base Sepolia pinned).
- Controlled x402 payment validated on Base Sepolia USDC, micro amount.
- DeFi Guardian mock risk report adapter.
- Persistent JSONL audit logs for buyer and seller events.
- Local audit summary CLI with human and JSON output.
- Static, self-contained local dashboard rendered from the same KPIs.
- Dashboard export snapshots.
- One-command local demo (`demo:local`) that exercises the full
  dry-run + mock + dashboard flow safely.

Not yet implemented:

- Real DeFi Guardian engine integration (still mock adapter).
- Hosted seller endpoint.
- Agent or MCP buyer integration.
- AI treasury / payment router.
- Production auth, billing surface, or screenshots in the repo.
